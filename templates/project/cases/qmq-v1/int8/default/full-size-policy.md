# qmq-v1 全尺寸测试范围

默认预设是 **192 个唯一 shape 的固定测试矩阵**。X1 为 `[M,K]`，X2 为 `[N,K]`，输出为 `[M,N]`，采用 INT8 输入、INT32 累加语义及逐阶段 FP32 缩放和量化。

| 维度 | 测试选点包围范围 |
| --- | --- |
| M | 1～8192 |
| N | 1～32769 |
| K | 1～8192 |

范围描述选点边界；没有穷举笛卡尔积，任意 kernel 也不因此获得整个区间的支持声明。准确清单以配置 `case_suite` 指向的 JSON 为准。qmq-v1 按 shape 路由，因此同一 suite 中每个 shape 只出现一次。

## 选点组成

| 分组 | 数量 | 用途 |
| --- | ---: | --- |
| smoke | 4 | 保留旧的 16×32×64、32×32×64、64×64×128、128×64×256 |
| tiny | 6 | 极小尺寸、零行和全零输入 |
| m-boundary | 29 | M 的对齐、尾块和多核分配边界 |
| n-boundary | 36 | N 的对齐及 2048/4096/16384 等路由边界，延伸到 32769 |
| k-boundary | 31 | K 的 32 对齐、128/1024 路由边界和长归约，延伸到 8192 |
| representative | 24 | 不同维度的组合、大输出和高计算量矩阵 |
| historical | 62 | 从既有 v235 的 542 个 shape 中补充维度组合 |

包含 15/16/17、31/32/33、63/64/65 等对齐附近点，N=2047/2048/2049、4095/4096/4097、16383/16384/16385，以及 K=127/128/129、1023/1024/1025、4095/4096/4097。

大尺寸示例：4096×2048×256、64×4096×1024、16×32769×129、8192×17×1024、4096×1536×1024、2048³、4096³、128×128×8192。最大维度不会全部同时取到上界。seed 固定为 42；2×2×2 使用 `zero-row`，3×5×7 使用 `all-zero`，其余使用 `random`。

## 全尺寸完成与支持范围

- `full` 对这 192 个 case 逐项记账。每个交付 revision 由其编写 subagent 完成测试并提交回执；Chief 的设备探测和参考数据生成不替代候选测试。
- 实现可明确只支持子域；不支持的 case 保留 `UNSUPPORTED` 及原因，不换其他 kernel 代跑。`PASS`、有效计时数和不支持数分别报告。不能为了通过测试删掉大 case、伪称不支持或把失败改成成功。
- 先用 probe 调试，再做交付 full。超时或资源不足保留真实状态，结合源码与设备限制修正实现或支持声明；完成记账不等于通过全部尺寸。
- 推荐范围仅包含实际正确且具有有效设备计时的 case。未测点和新范围不继承旧 4-case 成绩。机制假设、kernel 性能和集成选择分别判断。
- 有效提交后程序自动按 case shape 集成；不让 Chief 补测或手动拼装。

## 成本与固定数据

全部输入与 golden 二进制约 **201.5 MiB（211,292,067 bytes）**。选择脚本限制在 256 MiB 内，以适配当前把 case 文件编码到一个 JSON 请求中的 SSH 传输。base64 约另增三分之一体积，运行还需要解析缓冲、临时文件及候选设备内存；这不是设备内存预算。

oracle 按块生成；满足整数精确表示条件时用 FP64 矩阵乘得到精确整数点积，仍检查 INT32 范围并保留后续逐阶段 FP32 语义。生成完成后固定输入和 golden 哈希；CPU 参考答案不是 NPU 成绩。

真实 full 对每个支持且正确的 case 分别采样并采集设备执行证据。192 个 case 的传输和 profiler 成本应计入预算；串行标量基线在 4096³ 等 case 上可能超时。预算不足就报告实际完成范围，不缩减冻结 suite 来宣称完成。

## 新项目与旧项目

新项目默认写入本预设，设备准备成功后异步生成并固定数据。取消生成会清理本次临时目录；已生成 case 可重用，最终 suite 仅在全部数据就绪后写回。

已有固定 suite 和历史研究快照保持原样。扩展旧项目时，在没有进行中研究的情况下，由 Chief 将新预设保存为新的 `asc/case-suite-wide.json`，更新 `meteor.config.json.case_suite`，使用匹配版本的通用运行工具并准备数据，再启动下一轮。旧文件和回执保留。仅完成旧 4-case 时应写成“小尺寸 smoke 全集”，不能称为本预设的 192-case 完成。

## 来源与自主决策

用户要求检查既有 kernel 并扩大范围。192 个选点、上界、分组和传输预算由 Agent 提出。历史输入为 `v235_exact.json`，542 个唯一 shape，SHA256 `8cabf3ec986879e7337690323d5ea4bca61bf30fd4c6ccd7558f68bac7a65073`；它提供部分选点，K=8192 和部分大矩阵是新增点。目录存在不证明通过。

概念参考 NVIDIA CUTLASS 的显式 M/N/K 尺寸与验证配置：[profiler 文档](https://github.com/NVIDIA/cutlass/blob/main/media/docs/cpp/profiler.md)（2026-09-24 查阅）。[NumPy 2.3 matmul 文档](https://numpy.org/doc/2.3/reference/generated/numpy.matmul.html)说明可使用优化 BLAS；FP64 精确整数条件 `K*16384 <= 2^53` 是项目数学推导。没有复制厂商代码，也不把本预设参数称为厂商推荐。
