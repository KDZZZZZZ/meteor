# 真实设备初始化和实验凭据修复

## 人类设计

初始化不生成占位设备配置。chief 调试设备并生成硬件报告；测试和分析方法依据厂商官方文档写入现有两个 skill。研究保持一名连续上下文的 subagent、一份 persona。假设结论与性能排名独立；提交 kernel 的全尺寸测试由作者负责，入库后自动集成。

## Agent 自主决策

- 默认状态为 `unconfigured`。显式 mock 只用于测试/演示；未完成硬件探测禁止启动研究。
- 增加 chief 工具 `meteor_hardware_probe`，只引用集中 SSH profile。保存原始探测结果、可读报告、配置绑定和诊断；只有真实运行时信息及编译、launch、正确性、设备执行证明齐全才就绪。
- 普通性能采样与 profiler 设备证明分开；真实 PASS 行必须有匹配目标 kernel 的设备任务。CPU fallback、隐含数据搬运不能作为设备 kernel 性能验收。
- 完整公开提交 JSON schema，自动绑定会话身份；冻结之前验证入库必需字段。统一 UTF-8 输入输出，报告链接来自测量凭据。
- 工具接受模块目录或 `kernel.json`，能力不支持时返回可用指标，不让 agent 猜接口。

## 成熟实现借鉴

Ascend 官方 ACL event、运行时 SoC/内存查询、平台架构查询、CANN 9.0 msprof 和官方 msopprof 指南。具体接口、链接和版本限制见 `docs/ascend-measurement-guide.md` 及 skill 的 reference 文件。只借鉴接口和测量方法；真实效果由本机 SSH 实测决定。

## 验证

回归覆盖初始化不冒充硬件、未就绪与未准备 case 的拦截、硬件报告绑定、稳定环境身份、目标设备证明、提交字段/中文入库/权威链接。运行测试、语法检查、构建和类型检查；真实设备操作由 WebUI 中的 chief 执行。历史研究与冻结凭据保持可追溯，不回写旧结论。

Chief 已自动发现集中配置，定位并修复项目 msprof 输出参数，得到 READY 报告：Ascend910_9362 / dav-2201、健康 OK、add 编译与正确性通过、5 条匹配目标任务。首轮研究的无 kernel、INCONCLUSIVE 提交已回传并自动跳过集成；这不代表性能目标完成。对应过早停止问题已写入现有 persona/skill，后续按新快照验证。

本地验证：最终 127/127 测试通过，无跳过；语法检查 55 个源文件、构建、类型检查、diff 检查通过。DSH 0.1.7-alpha.2 原生 Web profile 验证通过；该兼容性检查不发模型请求，真实 chief 测试另行记录。

最后一轮 WebUI 中，chief 再次自行探测并得到 READY 报告，但研究 `qmq-v1-cube-one-round` 失败：subagent 只写了模块清单，缺少声明的源码；随后改写了 chief 指定假设的字段，未通过提交校验。没有有效 kernel、全尺寸性能数据或集成版本。后续修复明确了研究数量与实验预算的区别、源码缺失后的同实验重试，并让假设校验列出具体字段差异。这些修复通过回归验证，尚未证明模型在下一轮能完成真实算子研究。
